0. The toolkit: notation, shapes, derivatives

Notation. X is the data table: m rows (samples) × n columns (features). x(i) is row i, xj is column j, and xj(i) is one cell. y holds the targets, one per row. θ (or w) holds the weights, one per feature.

Shapes rule everything. A matrix product (a, b) @ (b, c) gives (a, c): the inner numbers must match. So X (m, n) @ θ (n,) gives (m,), one prediction per row. XT (n, m) @ error (m,) gives (n,), one number per weight.

Derivatives you need. d/dx of x² is 2x; of ex is ex; of ln x is 1/x. Chain rule: if J depends on h, and h depends on θ, then dJ/dθ = (dJ/dh)·(dh/dθ). Every gradient in this course is the chain rule.

Partial derivative: ∂J/∂θ2 means "treat every other θ as a constant". So for h = θ1x1 + θ2x2, ∂h/∂θ2 = x2.

Learning in one sentence: pick a model h, pick a loss J that measures how wrong it is, then change the parameters to make J small (with gradient descent or a formula).

1. Linear regression and gradient descent

Idea. Predict a number as a weighted sum of the features: ŷ = θ0 + θ1x1 + … + θnxn. Adding a column of 1s to X lets θ0 (the intercept) ride along, so ŷ = Xθ.

Loss. J = ½ Σ (ŷ(i) − y(i))². Squaring makes all errors positive and punishes big ones; the ½ cancels later.

Gradient (chain rule). For one row: ∂J/∂θj = (ŷ − y)·xj. The ½ cancels the 2 from the square, and xj comes from ∂ŷ/∂θj. For all rows, add them up: ∂J/∂θ = XT(ŷ − y).

Update. θ ← θ − α·gradient, where α is the learning rate (a small number like 0.01). The gradient points uphill, so subtracting it goes downhill.

Five steps every iteration: predict ŷ = Xθ → error e = ŷ − y → (loss J = ½Σe², just a score) → gradient XTe → update θ.

Variants. Batch uses all rows per update; stochastic (SGD) uses one row and updates θ before the next row; mini-batch uses a slice (e.g. 50 rows). One epoch = one pass over all rows. Scale features first, or large features (like gold prices) produce huge gradient components.

Worked example
  1. X = [[1, 2], [1, 3]] (first column = intercept), y = [5, 6], θ = [1, 1], α = 0.1.
  2. ŷ = Xθ = [1 + 2, 1 + 3] = [3, 4]; error e = ŷ − y = [−2, −2]; J = ½(4 + 4) = 4.
  3. Gradient XTe = [1·(−2) + 1·(−2), 2·(−2) + 3·(−2)] = [−4, −10].
  4. θ ← [1, 1] − 0.1·[−4, −10] = [1.4, 2]. New ŷ = [5.4, 7.4]: closer to y on average. Loss went down.

2. Regularization and the closed form

Overfitting: a model that fits the training data too closely (often with huge weights) does badly on new data. Regularization adds a penalty on weight size to the loss:

  • Ridge (L2): J + λΣθj². Gradient gets + 2λθ. Shrinks all weights a little.
  • Lasso (L1): J + λΣ|θj|. Gradient gets + λ·sign(θ). Pushes useless weights to exactly 0 (feature selection).
  • Elastic net: a mix of both. λ controls the strength: bigger λ = simpler model.

Closed form (normal equation). Instead of iterating, set the gradient to zero and solve: XT(Xθ − y) = 0 → θ = (XTX)−1XTy. Exact, no learning rate, but needs XTX invertible and becomes slow with many features. For a 2 × 2 matrix [[a, b], [c, d]], the inverse is (1/(ad − bc))·[[d, −b], [−c, a]].

Worked example (closed form)
  1. x = [1, 2, 3], y = [2, 4, 5]. With the intercept column, X = [[1, 1], [1, 2], [1, 3]].
  2. XTX = [[3, 6], [6, 14]], XTy = [11, 25].
  3. det = 3·14 − 6·6 = 6; inverse = (1/6)·[[14, −6], [−6, 3]].
  4. θ = (1/6)·[14·11 − 6·25, −6·11 + 3·25] = (1/6)·[4, 9] = [0.6667, 1.5]: the best line is ŷ = 0.67 + 1.5x.

3. Logistic regression (two classes)

Idea. For classification we want a probability between 0 and 1, not any number. So squash the linear score through the sigmoid: h = σ(z) = 1/(1 + e−z), with z = θTx. σ(0) = 0.5, big positive z → near 1, big negative → near 0. Predict class 1 when h ≥ 0.5 (that is, z ≥ 0).

Loss: binary cross-entropy. J = −Σ[y log h + (1 − y) log(1 − h)]. If y = 1 only −log h counts (small when h is near 1); if y = 0 only −log(1 − h) counts. Confident wrong answers are punished heavily.

Gradient. Chain rule through log, sigmoid and θTx simplifies to the same shape as linear regression: XT(h − y). (σ'(z) = σ(z)(1 − σ(z)) is what makes it cancel.)

Worked example
  1. x = [1, 2] (with intercept), y = 1, θ = [−1, 1]. z = −1 + 2 = 1; h = σ(1) = 0.7311.
  2. Loss = −log(0.7311) = 0.3133.
  3. Gradient = (h − y)·x = (−0.2689)·[1, 2] = [−0.2689, −0.5379].
  4. Update with α = 0.5: θ = [−1, 1] − 0.5·gradient = [−0.8655, 1.2689]. z grows, so h moves toward 1, which is correct.

4. Multinomial (softmax) regression: more than two classes

Idea. One weight vector per class: W has shape (n, k). Scores Z = XW (m, k). Softmax turns each row of scores into probabilities that sum to 1: pc = ezc / Σk ezk. Predict the class with the largest probability (argmax).

Labels as one-hot: class 2 of 3 becomes [0, 0, 1]. Loss: J = −Σ Y log H: only the log-probability of the true class counts. Gradient: XT(H − Y), shape (n, k) like W.

Worked example
  1. Scores z = [2, 1, 0]. ez = [7.3891, 2.7183, 1], sum = 11.1073.
  2. p = [0.6652, 0.2447, 0.09]: predict class 0.
  3. If the true class is 1, loss = −ln(0.2447) = 1.4076; the gradient row for this sample is p − y = [0.6652, −0.7553, 0.09].

5. Naive Bayes

Idea. Use Bayes' rule: P(y | x) = P(x | y)·P(y) / P(x). For classifying, the denominator is the same for every class, so compare P(y)·P(x | y) and pick the biggest.

  • Prior P(y): the share of training samples in each class.
  • Likelihood P(x | y): how typical these feature values are for that class.
  • "Naive": assume features are independent given the class, so P(x | y) = P(x1 | y)·P(x2 | y)·…

Gaussian NB (numeric features): for each class and feature, compute the mean μ and standard deviation σ; then P(xj | y) = (1/(√(2π)σ))·e−(xj − μ)²/(2σ²).

Multinomial NB (word counts): P(word | class) = (count of the word in that class + 1) / (total words in that class + vocabulary size). The +1 is Laplace smoothing: without it, one unseen word makes the whole product 0. In practice add logs instead of multiplying: score = log P(c) + Σ count(w)·log P(w | c).

Worked example (Gaussian NB, one feature)
  1. Class A heights: 160, 170 (μ = 165, σ = 5). Class B: 180, 190 (μ = 185, σ = 5). Priors 0.5 each. Classify 172.
  2. P(172 | A) = (1/(√(2π)·5))·e−(7)²/50 = 0.0798 × 0.3753 = 0.0299.
  3. P(172 | B) = 0.0798 × e−(13)²/50 = 0.0798 × 0.034 = 0.0027.
  4. Times the equal priors: A wins. 172 is closer to A's mean, measured in standard deviations.

6. K-nearest neighbors

Idea. No training at all: store the data. To classify a new point, find the k training points closest to it and take a majority vote of their labels.

Steps. Distance to every training point (squared Euclidean is fine) → sort (argsort) → take the first k → most common label (np.bincount(...).argmax()).

Choices. Small k: flexible but noisy (overfits). Large k: smooth but may ignore local structure. Use an odd k for two classes to avoid ties. Always scale features, because it is all distances. Prediction is slow for big data (a distance to every point).

Worked example
  1. Training: (1, 1) A, (2, 1) A, (5, 5) B, (6, 5) B, (5, 6) B. New point (2, 2), k = 3.
  2. Squared distances: (1, 1) → 1 + 1 = 2; (2, 1) → 0 + 1 = 1; (5, 5) → 9 + 9 = 18; (6, 5) → 16 + 9 = 25; (5, 6) → 9 + 16 = 25.
  3. Three nearest: (2, 1) A, (1, 1) A, (5, 5) B → majority A.

7. Support vector machines

Idea. Among all lines (hyperplanes) that separate two classes, choose the one with the widest margin: the biggest gap to the nearest points. Labels are −1 and +1; predict sign(wTx + b).

Math. Require y(wTx + b) ≥ 1 for every training point. The margin width is 2/‖w‖, so maximizing it means minimizing ½‖w‖² under those constraints. The points with y(wTx + b) = 1 exactly sit on the margin: the support vectors. Only they matter.

Solving. Lagrange multipliers α ≥ 0 turn it into the "dual" problem; a QP solver (cvxopt in the notebook) finds α. Then w = Σαiyixi and b = ys − wTxs for any support vector.

Soft margin: allow some violations, penalized by C (large C = strict, small C = wider, more tolerant margin). Kernels replace the dot product xTz with, e.g., (1 + xTz)p or e−‖x − z‖²/(2σ²), giving curved boundaries.

Worked example
  1. w = [1, −1], b = −3 (the notebook's line). Point (6, 1): wTx + b = 6 − 1 − 3 = 2 → class +1.
  2. Point (2, 3) with y = −1: wTx + b = 2 − 3 − 3 = −4; y·(−4) = 4 ≥ 1, so the constraint holds.
  3. Point (5, 1) with y = +1: 5 − 1 − 3 = 1, so y(wTx + b) = 1 exactly: a support vector.
  4. Margin width = 2/‖w‖ = 2/√2 ≈ 1.414.

G. SVM checks

G1Warm-up
w = [2, 0], b = −4. Classify (3, 7) and (1, 9). Which point lies on the margin if its label is +1: (2.5, 0) or (3, 0)?
Answer and solution
Answer: (3, 7) → +1 (2·3 − 4 = 2); (1, 9) → −1 (−2); (2.5, 0) gives 1 → on the margin
G2Warm-up
If ‖w‖ doubles, what happens to the margin width?
Answer and solution
Answer: It halves (width = 2/‖w‖).
G3Warm-up
Large C vs small C in a soft-margin SVM?
Answer and solution
Answer: Large C: few violations, narrow margin (may overfit). Small C: wider margin, more violations (more regularized).
