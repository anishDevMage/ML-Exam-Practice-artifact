How to practice (one dataset per session)

  1. Open a tasks notebook and do it under exam conditions: 2 hours, your notes and the professor's code allowed, no AI.
  2. Compare with the solution notebook cell by cell. Where your approach differs, decide which is better and why: that "why" is what the justification marks pay for.
  3. Re-type the template's functions from memory once (parse_number, the IQR clip, SMOTE, the scratch scaler, the scratch confusion matrix). Typing them once is what makes them fast on exam day.
  4. Do the next dataset with the template open and time how long each section takes.

Traps (each one has cost students marks)

  • pandas 3 and inplace: X_train["col"].fillna(value, inplace=True) (as in the Stroke notebook) modifies a temporary copy under pandas 3 and silently does nothing. Write X_train["col"] = X_train["col"].fillna(value).
  • Imputing only the training set: the Stroke notebook fills NaN in X_train but not X_test. Any NaN left in X_test makes LogisticRegression and SVC crash at predict time. Clean the whole dataset before splitting (as the template does), or impute both with the training statistics.
  • Balancing before the split: oversampled copies end up in the test set and inflate your scores. Split first, then balance the training set only. (Undersampling before the split, as in Stroke, is less harmful but the same principle applies.)
  • Fitting the scaler on the test set: fit on train, transform test. Never fit_transform the test set.
  • Judging by accuracy on imbalanced data: report precision, recall, F1 and AUC, and choose the best model by F1 or AUC.
  • AUC needs scores, not labels: pass predict_proba(X)[:, 1] (SVC needs probability=True) or decision_function, not predict.
  • Forgetting stratify: the task explicitly asks to keep class ratios; stratify=y is the 2 marks.
  • Old SciPy code: stats.mode(predictions)[0][0] from the bagging notebook returns one number on SciPy ≥ 1.11.

Sentences for the "justify" and "explain" marks

Adapt these to your numbers
  • Median imputation: "I used the median because it is robust to the outliers and skew in these columns, and dropping rows would lose too much of a 200-row dataset."
  • String errors: "Non-numeric text in a numeric column carries no information, so I converted it to NaN and imputed it, keeping the row's other valid values."
  • Outliers: "I flagged values outside Q1 − 1.5·IQR and Q3 + 1.5·IQR and clipped them to those limits: this keeps every row but stops entry errors (e.g. height 1724 cm) from dominating distance-based models."
  • Imbalance: "With 77% of samples in class 0, a model could reach 77% accuracy by always predicting 0 and never find the at-risk class, which is the one we care about."
  • SMOTE: "SMOTE creates new minority samples by interpolating between neighbours, which adds variety instead of exact copies (oversampling) and keeps all majority data (unlike undersampling). I applied it to the training set only to avoid leakage."
  • Scaling: "Logistic regression and SVM depend on distances and gradient sizes, so features with large units would dominate; standardizing gives each feature mean 0 and standard deviation 1. I fit the scaler on the training set only."
  • Cross-validation: "A single split gives one noisy estimate; 5-fold CV averages five estimates, each fold used once for validation, and its standard deviation shows stability."
  • Best model: "I chose the model with the highest F1 (and AUC) because the test set is imbalanced and accuracy rewards predicting the majority class."
  • Error analysis: "False negatives (missed positives) are the costly error here; lowering the decision threshold or using class_weight='balanced' trades some precision for higher recall."

Exam-day checklist

  • Check your Python environment the day before: pandas, numpy, scikit-learn, matplotlib, seaborn (imbalanced-learn is optional: the template has SMOTE from scratch).
  • Practice pushing a notebook to GitHub (2023 deliverable: a GitHub link).
  • Put Task 0 (student id and name) first.
  • Save the cleaned dataset (df_clean.to_csv(...)): it is a deliverable.
  • Leave 10 minutes for the short report: cleaning steps, EDA insights, model comparison, final model and its scores.
